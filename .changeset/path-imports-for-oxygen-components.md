---
'@wso2/oxygen-ui': minor
---

Add path imports for Oxygen components, for Material UI's, and for everything else on the barrel except the MUI X namespaces. `@wso2/oxygen-ui/TextField`, `@wso2/oxygen-ui/Sidebar` and one path for every other Oxygen component resolve to real modules, and `SearchBarWithAdvancedFilter` has a path of its own beside `SearchBar`. A path gives the component as its default export, with its parts, its hook and its types beside it, and it is the same object the barrel import gives. For `TextField` and `Select` that is the Override, not Material UI's component. Every Material UI path that has an index has an Oxygen path of the same name, so `@wso2/oxygen-ui/Button` and `@wso2/oxygen-ui/Box` give Material UI's component and an app never needs to import from `@mui/material`. They are generated from the installed Material UI. The `styles` and `utils` paths pass Material UI's through and add `createOxygenTheme`, `pxToRem` and `OxygenThemeType`, and `formatRelativeTime`; `colors` has a path. The paths of `TextField` and `Select` also carry the Material UI names the Overrides do not replace, such as `textFieldClasses`. Path imports need `moduleResolution` set to `bundler`, `node16` or `nodenext`.

`useAppShell`, `useNotifications` and `useThemeContent` each have a path, and so does every theme, named after its barrel name with the theme as the default export, so an app that imports one theme by path loads only that theme. `@wso2/oxygen-ui/OxygenUIThemeProvider` gives the provider as its default export and also carries `useThemeSwitcher`, its types and `createEmotionCache`. `Layout`, `ParticleBackground` and `version` each have a path, and the `version` path also carries Material UI's `major`, `minor`, `patch` and `prerelease`.

The package also publishes `@wso2/oxygen-ui/path-map.json`, which records for each name the path it lives on, whether it is that path's default export or a named export, and whether it is type-only. Declaration files now name their relative imports with an extension, so types resolve under `node16` and `nodenext`.
